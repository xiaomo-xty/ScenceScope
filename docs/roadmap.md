# SceneScope 项目路线图

> 本文是项目进度、当前任务和 Backlog 的唯一状态来源。

## 1. 执行原则

- 一次只保留一个“进行中”任务。
- 日期是节奏参考；里程碑未关闭时，不假装进入下一阶段。
- 遇到困难先缩小功能，不删除验证，也不为保留全部功能无限延期。
- 新想法先进入 Backlog，并回答它是否帮助正确展示资产、发现资产问题或形成工程证据。
- 三项均为“否”时移除；只有一项为“是”时默认排到 v0.1 之后。

状态只使用：`待办`、`就绪`、`进行中`、`阻塞`、`完成`、`移除`。

## 4. 里程碑完成标准

### M1：跨平台第一帧

- 从 Box GLB 字节提取首个静态 indexed primitive。
- 上传顶点和索引，完成基础 shader、深度测试和相机。
- 处理节点 TRS，渲染方向和比例正确。
- Windows 与 Web 使用同一份内部场景数据。
- 至少一个自动化解析测试。
- README 包含运行命令、截图、限制和已知问题。

### M2：从查看器到检查器

- 建立不绑定 glTF crate 的内部资产模型。
- 显示节点树、资源摘要和资产统计。
- 支持法线、UV 和 Base Color 纹理。
- Windows/Web 均能从用户选择的本地 GLB 读取字节；拖放可后补。
- 损坏、空或不支持的输入返回有分类的错误。
- 使用多个 Khronos Sample Assets 做回归测试。

### M3：规则与报告

- 实现 InspectionProfile、Diagnostic 和静态规则组合。
- 完成至少 5 条检查规则，每条有通过和失败测试。
- CLI 读取 GLB 并输出 JSON 报告。
- GUI、Web 和 CLI 的统计与诊断一致。
- 报告包含规则 ID、严重程度、对象位置、说明和建议。

### M4：工程化与发布

- 建立格式化、静态检查、测试和多目标构建检查。
- 对核心解析和规则执行建立 benchmark 基线。
- 使用 CPU profiler 或 RenderDoc 完成一次有证据的分析。
- 覆盖大文件、空场景、缺失属性和不支持扩展等失败路径。
- 发布 Windows 程序、Web Demo 和 `v0.1.0` 说明。

### M5：项目案例整理

- README 能在 60 秒内说明问题、方案、架构和运行方式。
- 提供 60～90 秒演示视频或 GIF。
- 保留架构决策、性能数据和一个完整调试案例。
- 技术文章只来自项目中实际解决的问题。

### M6：平台扩展

顺序固定为 Windows + Web、macOS + Linux、Android、iOS。没有经过真实环境构建和运行验证的平台，不得声明支持。

## 6. 当前风险

| 风险 | 影响 | 缓解方式 |
|---|---|---|
| Windows/Web 的坐标或渲染语义不一致 | 资产显示错误 | 共用内部模型；数值测试与固定视角运行证据 |
| glTF 扩展导致范围膨胀 | v0.1 无法按期收敛 | 只实现明确范围；其余诊断或分类失败 |
| 过早拆 crate 或设计插件 | 时间消耗在无消费者抽象上 | 第二个真实消费者出现后再提取 |
| 损坏 GLB 触发 panic 或过量分配 | 稳定性与安全性问题 | 校验长度/偏移/索引；加入失败和边界测试 |
| WebGPU/Surface 生命周期差异 | Web 或窗口恢复失败 | 保守 features/limits；分别进行真实运行验证 |
| 测试资产许可不清 | 无法公开仓库或演示 | 只使用可追溯资产并保留归属和许可证 |
| 把未验证平台写成已支持 | 项目说明失真 | 只声明真实构建和运行验证结果 |

## 7. 完成定义

任务只有同时满足以下条件才标记完成：

- 相关代码已格式化并通过静态检查。
- 与风险相称的自动化测试通过。
- 验收证据可以复现。
- 用户可见行为、限制或决策已同步到对应文档。
- 没有把后续里程碑能力表述为当前已支持。
