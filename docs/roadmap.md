# SceneScope 项目路线图

> 本文是项目进度、当前任务和 Backlog 的唯一状态来源。

## 1. 执行原则

- 一次只保留一个“进行中”任务。
- 日期是节奏参考；里程碑未关闭时，不假装进入下一阶段。
- 遇到困难先缩小功能，不删除验证，也不为保留全部功能无限延期。
- 新想法先进入 Backlog，并回答它是否帮助正确展示资产、发现资产问题或形成工程证据。
- 三项均为“否”时移除；只有一项为“是”时默认排到 v0.1 之后。

状态只使用：`待办`、`就绪`、`进行中`、`阻塞`、`完成`、`移除`。

M2-002 已完成，转换侧与渲染输入侧均已落地。

**转换侧**：`parse_asset_document` 覆盖场景、节点、多个 mesh primitive、材质与纹理的转换；UV（`TEXCOORD_0`）、对象名称与 Base Color 纹理（内嵌 PNG/JPEG，经 `libjpeg-turbo-rs` 0.8 解码为 RGBA8）均已接入，材质到纹理的引用已闭环。除 Box 回归外，测试使用手写 GLB fixture（`build_glb`）覆盖可选属性缺失、UV 数量不匹配、内嵌 PNG/JPEG、RGB/灰度展开与外部纹理拒绝等路径。

**渲染输入侧**：`AssetDocument::mesh_instances` 按声明序深度优先遍历默认场景、用 `visited` 去重并组合 TRS 世界变换（Core 5 条单测覆盖根序、DFS 顺序、共享节点、变换组合与空文档）；Windows/Web 入口改为从 `AssetDocument` 派生实例后创建 GPU 状态。旧的 `parse_first_mesh_primitive`、拥有式 `MeshInstance` 与无调用者的 `set_mesh`/`ObjectBinding::update` 已删除，`glam` 从 glTF 适配器移除（世界变换数学归 Core）。遍历顺序是契约，由「两个根节点」等用例钉住。

**证据**：21 个测试通过（Core 7 / glTF 10 / Render 4），`cargo release-check`、`cargo fmt --all --check` 与 wasm32 目标编译通过；桌面端画面与 M1 截图一致（迁移未改变像素）。决策记录见 [ADR-0003](adr/0003-asset-document-render-input.md)。

下一步：M2-003（Windows/Web 本地文件选择）。渲染器目前只绘制第一个网格实例；运行时换资产需要重新设计文档所有权与 GPU 资源重建（此前为此准备的 `set_mesh` 因无调用者已删除，将按真实需求重写）。

M2-003 的文件对话框选型已完成 spike 验证（2026-10-11，临时目录，未入库）：选用 `rfd` 0.17.2（MIT），两端统一走 `AsyncFileDialog::pick_file()` + `FileHandle::read()`——浏览器不支持路径、只返回字节，与架构边界的「文件以字节进入业务流程」一致。验证结论：

- Windows 原生编译通过，依赖仅 `windows-sys` / `raw-window-handle` / `log`；实测弹出原生对话框，选中 `Box.glb` 返回 1664 字节且魔数为 `glTF`，取消返回 `None`。
- `cargo check --target wasm32-unknown-unknown` 与 `wasm-pack build --target web --dev` 全链路通过；浏览器实测返回 1664 字节，取消返回 `None`。
- 已知约束：wasm 侧 `#[wasm_bindgen]` 的 async fn 需要 crate 直接依赖 `wasm-bindgen-futures`（Web 入口已有）；浏览器要求文件选择由用户手势触发；`FileHandle::path()` 在浏览器不存在，只能用 `read()`。

M2-003 已完成（2026-10-11）。两端都用 `AsyncFileDialog` 打开本地 GLB，并以字节调用同一转换入口：

- **Windows**：对话框在 worker 线程运行（模态对话框不占用 winit 事件循环），结果经 `EventLoopProxy<UserEvent>` 回传；用 `path()` + `std::fs::read` 读取以保留 IO 错误可见性（`FileHandle::read` 在 IO 失败时会 panic）。
- **Web**：`spawn_local` 驱动对话框并 `read()` 取字节（浏览器无路径）；`initialize_gpu` 把 `AssetDocument` 与 `GpuState` 一起交还给 `App`，以满足 `spawn_local` 的 `'static` 约束。
- **换资产**：`GpuState::set_mesh` 原子替换——所有可失败步骤完成后才更换状态，保留设备、管线、Surface 与相机；失败时旧资产留在屏幕上。
- **取消语义**：取消返回 `None`，在两端都不产生任何诊断。
- **验证**：桌面端与浏览器均实测加载 `CesiumMilkTruck.glb`（369,980 字节；Cesium / CC-BY-4.0，本地测试资产未入库）；非 GLB 输入在两端都保留当前画面并在 stderr / 控制台报错。过程中修复了对象 uniform buffer 缺少 `COPY_DST` 导致的 wgpu 校验 panic——该缺陷自 `set_mesh` 首次被真实调用才暴露。

M2-007 已完成（2026-10-11）：滚轮增量在 `wheel_notches` 中统一为「格」——行增量原样通过，像素增量按每格 100 像素折算。此前两端各自把原始值直接交给相机，而浏览器上报像素级增量（约 100/格），因此比桌面端灵敏约 100 倍，一格即触达距离上下限。换算收敛到 render crate 一处供两个入口共用，并由单测钉住「一个浏览器格 = 一个桌面格」；`zoom_camera` 的文档写明单位，避免调用者再次传入原始值。

M2-004 已于 2026-10-11 启动，目标是"能用的检查器"：浏览节点树、资源摘要与统计，并与视口双向联动。本轮范围（估算粒度 2h）：

- **前置——渲染正确性**：`MeshInstance` 增加 `node_id`/`mesh_id`/`primitive_index`（2h）；渲染器多实例绘制，按 `(mesh, primitive)` 去重几何、按实例提交世界变换，`GpuState::set_mesh` 改为 `set_instances`（6h）。渲染器目前只绘制第一个网格实例——`CesiumMilkTruck.glb` 有 2 个 mesh、4 个 primitive、5 个可达实例，因此只显示车身，多实例绘制是本轮要还的债。
- **界面接线**：`egui-winit` + `egui-wgpu` 集成进两个现有入口，按目标分别声明 features（wasm 需关掉依赖 `arboard` 的 `clipboard`），含输入门控（6h）。
- **界面内容**：新 crate `scenescope-ui` 的视图模型（4h）与 egui 面板——资源摘要、节点树、网格、材质、纹理（10h）。
- **联动**：选择状态 + 高亮 + 文本表达（第 8 节要求不能只靠颜色）+ 点击空白取消选中（6h）。
- **决策记录**：ADR-0004（2h）。

同一里程碑内的后续项按第 3 节排期执行：M2-005 错误分类与回归资产、M2-006 拖放、M2-008 双向拾取、M2-009 双语与字体、M2-010 材质可见、M2-011 PBR-lite。

**进度**：实例身份已完成（2026-10-12，`9375199`）——`MeshInstance` 增加 `node_id`/`mesh_id`/`primitive_index`，几何字段更名为 `geometry`；Core 测试 9 条通过，其中两条分别钉住节点维度与 primitive 维度的索引来源，并用 `std::ptr::eq` 正反两向把 ADR-0003 的零拷贝从"好处"提升为契约。ADR-0003 的旧结构代码块保留原样，只加一行指向 ADR-0004 的说明。

框架与分层决策见 [ADR-0004](adr/0004-gui-framework-and-ui-layering.md)。

## 4. 里程碑完成标准

### M1：跨平台第一帧

- 从 Box GLB 字节提取首个静态 indexed primitive。
- 上传顶点和索引，完成基础 shader、深度测试和相机。
- 处理节点 TRS，渲染方向和比例正确。
- Windows 与 Web 使用同一份内部场景数据。
- 至少一个自动化解析测试。
- README 包含运行命令、截图、限制和已知问题。

### M2：从查看器到检查器

- 建立不绑定 glTF crate 的内部资产模型。
- 显示节点树、资源摘要和资产统计。
- 支持法线、UV 和 Base Color 纹理。
- Windows/Web 均能从用户选择的本地 GLB 读取字节；拖放可后补。
- 损坏、空或不支持的输入返回有分类的错误。
- 使用多个 Khronos Sample Assets 做回归测试。

### M3：规则与报告

- 实现 InspectionProfile、Diagnostic 和静态规则组合。
- 完成至少 5 条检查规则，每条有通过和失败测试。
- CLI 读取 GLB 并输出 JSON 报告。
- GUI、Web 和 CLI 的统计与诊断一致。
- 报告包含规则 ID、严重程度、对象位置、说明和建议。

### M4：工程化与发布

- 建立格式化、静态检查、测试和多目标构建检查，且门禁覆盖每个受支持目标：host 的 fmt / clippy / test / release-check，以及 wasm32 目标的 check 与 clippy（`#[cfg(target_arch = "wasm32")]` 代码在 host 门禁下完全不可见，M2-003 收尾时曾因此一次性暴露 4 个未检查的警告）。
- 对核心解析和规则执行建立 benchmark 基线。
- 使用 CPU profiler 或 RenderDoc 完成一次有证据的分析。
- 覆盖大文件、空场景、缺失属性和不支持扩展等失败路径。
- 发布 Windows 程序、Web Demo 和 `v0.1.0` 说明。

### M5：项目案例整理

- README 能在 60 秒内说明问题、方案、架构和运行方式。
- 提供 60～90 秒演示视频或 GIF。
- 保留架构决策、性能数据和一个完整调试案例。
- 技术文章只来自项目中实际解决的问题。

### M6：平台扩展

顺序固定为 Windows + Web、macOS + Linux、Android、iOS。没有经过真实环境构建和运行验证的平台，不得声明支持。

## 6. 当前风险

| 风险 | 影响 | 缓解方式 |
|---|---|---|
| Windows/Web 的坐标或渲染语义不一致 | 资产显示错误 | 共用内部模型；数值测试与固定视角运行证据 |
| glTF 扩展导致范围膨胀 | v0.1 无法按期收敛 | 只实现明确范围；其余诊断或分类失败 |
| 过早拆 crate 或设计插件 | 时间消耗在无消费者抽象上 | 第二个真实消费者出现后再提取 |
| 损坏 GLB 触发 panic 或过量分配 | 稳定性与安全性问题 | 校验长度/偏移/索引；加入失败和边界测试 |
| glTF 图片解码依赖的安全背书在途 | 损坏或恶意图片在解码路径可能触发未发现的内存问题（当前无已知活 UB） | `libjpeg-turbo-rs` 0.8 上游 2026-08 审计发现的 safe API 缺陷（P4-135..138）均已修复关闭，但 P4-139/P4-141 未关闭、无正式内存安全保证；只使用最小接口面（`decompress_to`/`load_png_from_bytes`，`compress` 仅测试）并分类返回错误；上游背书关闭或 0.9.0 发布时复查，必要时回退 `image` 0.25（zune-jpeg），隔离点在 `convert_texture` 一处 |
| 内嵌图像缺失 mimeType 触发 `gltf` 依赖内部 panic | 损坏或恶意输入可能直接崩溃解析入口 | M2-005 错误分类阶段做前置校验或隔离；已记录于 README 已知问题 |
| WebGPU/Surface 生命周期差异 | Web 或窗口恢复失败 | 保守 features/limits；分别进行真实运行验证 |
| 测试资产许可不清 | 无法公开仓库或演示 | 只使用可追溯资产并保留归属和许可证 |
| 把未验证平台写成已支持 | 项目说明失真 | 只声明真实构建和运行验证结果 |

## 7. 完成定义

任务只有同时满足以下条件才标记完成：

- 相关代码已格式化并通过静态检查。
- 与风险相称的自动化测试通过。
- 验收证据可以复现。
- 用户可见行为、限制或决策已同步到对应文档。
- 没有把后续里程碑能力表述为当前已支持。
