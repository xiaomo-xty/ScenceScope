# ADR-0004：GUI 框架与界面分层

- 状态：已接受
- 日期：2026-10-11
- 决策人：项目负责人

## 背景

M2-004 要实现"浏览节点、网格、材质、纹理及核心统计"的界面。产品规格第 11 节一直把 GUI 框架的选择挂在"待真实交互需求明确后再定"——现在需求明确了：只读浏览加选中联动（双向），文本输入与资产编辑不在范围内（第 10 节排除资产编辑）。

既是约束也是候选筛选条件的有三条：

1. 界面必须同时存在于 Windows 原生与浏览器（M2 的两个平台入口），且两端共用逻辑。
2. Core 不依赖 wgpu、winit、egui 或平台 API（第 8 节）；GUI、Web、CLI 必须对同一资产产生相同统计（第 9 节第 5 条）。
3. 关键状态不能只用颜色表达，主要命令可通过键盘访问（第 8 节）。

## 决策

1. **采用 egui 0.36.2，通过 `egui-winit` + `egui-wgpu` 集成进现有入口，不采用 eframe。** 版本与现有技术栈精确对齐：`egui-wgpu 0.36.2` 要求 `wgpu ^30.0`（现有 30.0.0）、`egui-winit 0.36.2` 要求 `winit ^0.30.13`（现有 0.30.13）、`bytemuck ^1.25`（现有 1.25.2）、`web-sys ^0.3.103`（现有 0.3.104），因此不会引入第二份 wgpu 或 winit。
2. **界面代码放入新 crate `scenescope-ui`，并分两层：**
   - **视图模型层**：从 `AssetDocument` 派生"要显示什么"（节点树扁平化、资源摘要、统计格式化、字符串查表），不依赖 egui，可单元测试。
   - **egui 渲染层**：只负责把视图模型画出来。

   这样第 9 节第 5 条的"三端统计一致"由单一数据来源保证，而不是三处各写一遍。
3. **字符串从第一天起走查表**，首版只放英文。中文表与字体属于 M2-009，届时是加法而不是改造。
4. **feature 按目标分别声明**：`egui-winit` 的默认 features 含 `clipboard`（依赖 `arboard`，而 `arboard` 没有 web 后端，其启用条件是 `cfg(not(target_os = "android"))`，对 wasm32 成立），因此 wasm 目标必须用 `default-features = false`。
5. **平台入口保持薄**：egui 的输入门控（面板消费的事件不再传给相机）与字体加载（桌面 `include_bytes!`、Web 运行时 fetch 自托管文件）留在各自入口。
6. **实例身份先于界面联动**：`MeshInstance` 增加 `node_index` / `mesh_index` / `primitive_index`。`node_index` 是"树（节点维度）→ 实例"的唯一桥梁（一个节点可对应多个 primitive 实例），`mesh_index` 让渲染器按 mesh 去重几何。`GpuState::set_mesh` 的语义随之改为"替换整个绘制列表"，重命名为 `set_instances`。
7. **选中联动双向**：树→视口用实例身份高亮；视口→树用 CPU 射线求交（纯函数、可单元测试，且必须与渲染管线的背面剔除语义一致）。点击空白取消选中。
8. **不写抛弃式 spike**：以"两端各画出一个最小面板并验证输入门控与 feature 组合"作为第一步真实实现，替代一次性验证代码。

## 考虑过的选项

- **eframe（一体化框架）**：拒绝。它接管事件循环与 App 结构，与"平台入口薄、共享逻辑在 crate"的既有分层冲突；两个入口需要重写，而且会多一层对 wgpu/winit 版本的绑定。
- **iced / slint**：拒绝。各自带渲染器与事件循环，需要把 3D 视口嵌入其 widget 体系；不绑定现有 wgpu 30，升级与调试成本都更高。
- **用 wgpu 手绘界面**：拒绝。树、滚动、布局与文本光栅化都要自研，与 v0.1 的时间预算不相称。
- **Web 用 DOM/CSS、桌面用原生控件**：拒绝。两端界面代码不共享，与第 8 节、第 9 节的跨入口一致性目标冲突，工作量也翻倍。
- **让视图模型依赖 egui**：拒绝。会把界面框架泄漏进数据层，统计一致性无法脱离窗口独立测试。
- **视口拾取用 GPU 离屏 ID 缓冲**：暂缓。它更贴近"所见即所选"，但读回是异步的、两端都要写回调；CPU 射线求交是可单测的纯函数，先满足 M2-004。
- **现在就做中英双语并嵌入 CJK 字体**：推迟到 M2-009。全量 Noto Sans SC 静态字体 8.45 MB（可变字体 16.95 MB），直接进 wasm 会让 Web Demo 首屏多下载数 MB；先留出字符串查表的缝，不提前付这份成本。

## 后果

好处：

- 界面与渲染共用同一个 `wgpu::Device`、`Queue` 与窗口，不引入第二套渲染栈。
- Core 保持不依赖界面框架；统计与诊断的单一来源使跨入口一致性可测。
- 视图模型可单元测试，不需要窗口或 GPU 设备。

代价：

- **wgpu / winit / egui 的版本被绑定在一起**：`egui-wgpu` 写死 `wgpu ^30`，跨大版本升级必须三者同步，否则树中会出现两份 wgpu（`cargo tree -d` 重复依赖门禁失败，且 `wgpu31::Device` 与 egui 期望的类型不兼容，编译无法通过）。
- 两个入口各多出一段胶水代码（事件转发与门控、egui 纹理上传、字体加载）。
- Web 端多一条运行时字体 fetch 路径与额外的 `web-sys` features（M2-009）。
- 全量 CJK 字体带来 MB 级资源与相应的许可记录工作（M2-009）。

## 重新评估条件

- egui 或 wgpu 出现大版本升级需求时，先确认三者能否同步升级；不能同步则评估更换界面方案或暂缓升级。
- 界面需要文本输入或输入法（搜索、筛选、重命名）时，重新评估 egui 的输入法支持与键盘可达性的实现方式。
- 实例数达到数千、CPU 射线求交成为瓶颈时，改为 GPU 拾取。
- wasm 体积超出 Web Demo 可接受范围时，评估界面功能裁剪或按需加载。
